# 数据库设计

实际结构以 `server/src/main/resources/db/migration` 中的 Flyway 脚本为准。

| 表 | 作用 | 关键约束 |
| --- | --- | --- |
| `app_user` | 用户及风险状态 | 只保存脱敏手机号、昵称和风险状态 |
| `user_role` | 用户角色 | `(user_id, role)` 唯一 |
| `community` | 合作小区 | 名称、经纬度、启用状态 |
| `vehicle` | 用户车辆 | 车牌标准化后唯一；软停用 |
| `parking_space` | 共享车位 | 归属小区和车位主；带审核状态和版本号 |
| `availability_slot` | 一次性共享时段 | 开始早于结束；仅免费模式 |
| `booking` | 预约订单 | 预约号唯一；活动订单参与重叠校验 |
| `check_record` | 入场/离场记录 | 保存类型、操作人和实际发生时间 |
| `review` | 订单评价 | `booking_id` 唯一，免费 MVP 每单一次评价 |
| `complaint` | 投诉 | 关联订单、发起人、状态和处理结论 |
| `audit_log` | 管理审计 | 记录对象、动作、操作者和摘要 |

## 时间与删除

- 数据库存储 UTC 时间戳，接口使用 ISO-8601。
- 核心业务数据不物理删除；车辆、车位、小区和时段通过状态停用。
- 所有可并发修改的聚合根包含 `version` 乐观锁字段。

## 隐私

手机号使用脱敏值；车牌和详细车位信息不写入普通业务日志。查询接口根据预约参与关系决定是否返回完整车位号和入场说明。车位证明材料存储将在后续认证阶段接入。
