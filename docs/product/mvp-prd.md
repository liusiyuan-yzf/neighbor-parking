# 免费车位共享 MVP PRD

## 1. 目标

在单个或少量合作小区验证：住户愿意发布确定的空闲车位时段，附近车主能够可信地完成查询、预约、入场和离场。

## 2. 成功标准

- 有效共享时段能够被查询并成功预约。
- 车位不会被重复预约。
- 订单可以完整流转到已完成，异常可以追踪。
- 未预约用户无法获得精确车位和入场敏感信息。
- 物业可以审核供给并处理争议。

## 3. 用户角色

| 角色 | 描述 | 关键权限 |
| --- | --- | --- |
| 普通用户 | 需要临时停车的车主 | 搜索、预约、管理车辆、评价和投诉 |
| 车位主 | 已认证且拥有可共享车位的住户 | 普通用户权限、车位和时段管理 |
| 物业管理员 | 负责合作小区运营 | 小区内车位审核、订单和投诉查看 |
| 平台管理员 | 平台运营人员 | 全局管理、风控和审计 |

## 4. 核心规则

### 4.1 搜索

- 只返回审核通过、未停用、存在覆盖目标时间的已发布时段的车位。
- 搜索时间必须晚于当前时间，结束时间必须晚于开始时间。
- 搜索结果显示小区、距离、允许车型、时段和认证状态，不显示完整车位编号。

### 4.2 预约

- 预约人必须拥有一辆启用状态的车辆。
- 预约区间必须完全包含在发布时段内。
- 同一车位的 `CONFIRMED` 或 `IN_USE` 订单不得发生时间交叉。
- 车位主不能预约自己的车位。
- 免费 MVP 的订单金额固定为 0，不创建支付记录。

### 4.3 取消与使用

- `CONFIRMED` 且尚未开始的订单可由预约人取消。
- 预约开始前 30 分钟起允许确认入场；超出结束时间仍可完成，但记录实际离场时间。
- 只有 `IN_USE` 订单可以完成。
- 取消在订单中记录原因与更新时间；入场和离场通过签到记录保存操作人和时间。

### 4.4 隐私

- 搜索结果只展示停车区域和脱敏编号，例如 `B2-***`。
- 预约成功后，订单参与者及管理员才能查看完整编号和入场说明。
- 车牌在非本人界面显示为 `京A·***8` 形式。
- 证明材料只保存受控对象键，不提供公开 URL。

### 4.5 审核与投诉

- 新车位默认为 `PENDING_REVIEW`。
- 审核通过后才能发布时段；驳回必须填写原因。
- 完成、取消或使用中的订单可以发起投诉。
- 投诉从 `OPEN` 流转为 `PROCESSING`，最终为 `RESOLVED` 或 `REJECTED`。

## 5. 非功能需求

- 所有写接口进行服务端参数校验和权限校验。
- 关键写操作支持幂等或拒绝非法重复状态变更。
- API 错误返回稳定错误码、请求路径和时间。
- 数据库时间统一存储为 UTC，客户端按 `Asia/Shanghai` 展示。
- 关键管理操作保留审计日志。
- 生产配置不允许启用开发身份登录。

## 6. 本期不包含

支付、退款、结算、优惠券、动态定价、硬件控制、后台持续定位、跨城市运营和自动客服。
